# Design

## Context

- `Clavus.Shared.Abstractions` só tem contratos (`IModule`) e não depende de EF Core. `Clavus.Shared.Infrastructure` já referencia `Abstractions` e contém o `ModuleDbContext`, base de todo DbContext de módulo, que aplica schema do módulo, snake_case (via `ConfigureModuleDbContext`) e `DateTime` → `timestamp without time zone`.
- Os contextos de módulo chamam `base.OnModelCreating` **antes** de registrar suas entidades (ver `TestModuleDbContext`). Qualquer configuração feita em um laço sobre as entidades dentro do `OnModelCreating` da base não enxergaria essas entidades.
- Colunas `timestamp without time zone` não aceitam `DateTime` com `Kind = Utc` (o Npgsql lança exceção). O projeto já usa `DateTime.Now` / `Unspecified`.
- O PostgreSQL de desenvolvimento é a versão 18 (`docker-compose.yml`), que tem a função nativa `uuidv7()`.
- Projetos `Shared` exigem XML doc em todo membro público (CS1591 ativo, `TreatWarningsAsErrors`).

## Goals / Non-Goals

**Goals:**
- O módulo só escreve `public sealed class Produto : Entity` e ganha as cinco colunas, com defaults, índice e preenchimento de datas, sem configuração adicional.
- As entidades de domínio continuam sem depender de EF Core.
- Defaults também no banco, para inclusões feitas fora da aplicação (scripts, carga de dados).

**Non-Goals:**
- Hora em UTC ou abstração de relógio (`TimeProvider`): segue o padrão atual de hora local.
- Preencher datas em operações em lote (`ExecuteUpdate`/`ExecuteDelete`), que não passam pelo change tracker.

## Decisions

### 1. `Entity` em `Clavus.Shared.Abstractions`, namespace `Clavus.Shared.Abstractions.Domain`

Classe abstrata POCO, sem atributos de EF:

| Propriedade | Tipo | Acesso | Valor inicial |
|---|---|---|---|
| `Id` | `long` | `get; private set;` | gerado pelo banco |
| `Identifier` | `Guid` | `get; private set;` | `Guid.CreateVersion7()` |
| `CreateIn` | `DateTime` | `get; private set;` | preenchido ao salvar |
| `UpdateIn` | `DateTime` | `get; private set;` | preenchido ao salvar |
| `IsActive` | `bool` | `get; set;` | `true` |

- `Identifier` é gerado no construtor, para que a entidade tenha identidade pública antes de ser salva (útil para retornar no response ou relacionar objetos ainda não persistidos).
- Setters privados: só o EF (que grava por backing field) e o `ModuleDbContext` mexem em `Id` e nas datas.
- *Alternativa descartada:* colocar em `Clavus.Shared.Infrastructure`. Obrigaria a camada de domínio dos módulos a depender de EF Core/Npgsql.

### 2. Configuração por convenção de modelo (`IModelFinalizingConvention`)

Nova convenção `EntityConvention` em `Clavus.Shared.Infrastructure/Persistence`, registrada em `ModuleDbContext.ConfigureConventions` (`configurationBuilder.Conventions.Add(...)`). Na finalização do modelo, para cada tipo raiz (sem tipo base mapeado) cujo CLR type herda de `Entity`:

| Coluna | Configuração |
|---|---|
| `id` | chave primária, `bigint generated by default as identity` (padrão do Npgsql para `long`) |
| `identifier` | `uuid not null`, `default uuidv7()`, índice único `ix_<tabela>_identifier` |
| `create_in` | `timestamp without time zone not null`, `default localtimestamp` |
| `update_in` | `timestamp without time zone not null`, `default localtimestamp` |
| `is_active` | `boolean not null`, `default true` |

- Os defaults de banco ficam com `ValueGenerated = Never`: a aplicação **sempre** envia o valor. Sem isso, o EF trataria `false` em `IsActive` (e `Guid.Empty`/`DateTime.MinValue`) como "não informado" e deixaria o banco aplicar o default, o que impediria gravar entidade inativa.
- `localtimestamp` (e não `now()`) porque devolve `timestamp without time zone` direto, sem conversão implícita de `timestamptz`.
- Por ser convenção, a configuração explícita de um módulo (`IEntityTypeConfiguration`) tem precedência, e a ordem de registro das entidades no `OnModelCreating` não importa.
- Nomes de tabela, colunas e índice saem do `UseSnakeCaseNamingConvention()` já existente; nada é nomeado à mão.
- *Alternativa descartada:* laço sobre `modelBuilder.Model.GetEntityTypes()` no `OnModelCreating` da base. Não vê entidades registradas depois do `base.OnModelCreating` (ver Context).
- *Alternativa descartada:* `IEntityTypeConfiguration<T>` base para o módulo herdar. Depende de cada módulo lembrar de usar.

### 3. Preenchimento de datas no `SaveChanges` do `ModuleDbContext`

`ModuleDbContext` sobrescreve `SaveChanges(bool)` e `SaveChangesAsync(bool, CancellationToken)` e, antes de chamar a base, percorre `ChangeTracker.Entries<Entity>()` com um único `DateTime.Now`:
- `Added`: `CreateIn` e `UpdateIn` = agora.
- `Modified`: `UpdateIn` = agora; `CreateIn` volta ao valor original e é marcado como não modificado.
- `Unchanged`: nada (entidade salva sem alteração não muda `UpdateIn`).

O `ChangeTracker.DetectChanges()` é chamado antes do laço para que alterações em entidades rastreadas por snapshot sejam vistas como `Modified`. As duas sobrecargas sem `acceptAllChangesOnSuccess` já delegam para essas, então basta sobrescrever as duas.

- *Alternativa descartada:* `SaveChangesInterceptor`. Teria de ser registrado em `ConfigureModuleDbContext` e em cada factory de teste/design-time; o override no contexto base vale para qualquer forma de criação do contexto.

### 4. Alterações de banco

Nenhum schema de módulo é alterado nesta change (não há módulos de negócio). Os testes de `Clavus.Shared.Infrastructure.Tests` ganham uma entidade fictícia `ProdutoTeste : Entity` no `TestModuleDbContext` (schema `teste_convencoes`, tabela `produto_teste`), com a migration `20261026_EntidadeBase`, gerada pelo `dotnet ef` com o nome prefixado pela data.

Dependências entre módulos: nenhuma nova. Só `Infrastructure` → `Abstractions`, que já existe.

## Risks / Trade-offs

- [PostgreSQL < 18 não tem `uuidv7()`] → a migration falha ao criar a tabela. Decisão: o projeto passa a exigir PostgreSQL 18 (o `README.md` hoje diz "16 ou superior" e será atualizado; o `docker-compose.yml` já usa a 18). Inclusões pela aplicação não dependem da função.
- [`ExecuteUpdate` em lote não atualiza `update_in`] → limitação documentada no XML doc da `Entity`; quem usar `ExecuteUpdate` define `UpdateIn` na própria expressão.
- [`DateTime.Now` depende do fuso do servidor] → mesmo comportamento já adotado pelo projeto para `timestamp without time zone`; troca para outro relógio fica fora desta change.
- [Entidades de herança (TPH/TPT)] → a convenção configura só o tipo raiz; os derivados herdam as colunas da raiz.

## Migration Plan

Sem impacto em ambientes existentes: não há tabelas de negócio. A migration de teste só roda no banco temporário dos testes. Rollback = reverter o commit.
